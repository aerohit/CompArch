Reference · Hardware and programming models

A map of parallel machines and programs

"SIMD" and "SPMD" are two answers to two different questions. SIMD is one way hardware can run many operations at once; SPMD is one way to write a program that has many operations to run. There are several of each, and any real system mixes them. This page lays them all out, using the same small job for every machine and the same small computation for every programming model, so you can compare them side by side.

Keep asking two separate questions: how does the hardware get many operations done at once? and how does the program express that there are many operations? A compiler or runtime maps the second onto the first, and the same program can run on very different machines.
Section 1

Two separate questions, one mapping

A programming model is the abstraction you write in: what "parallel" looks like in the code, how work is divided, and how the pieces communicate. A hardware organization is what physically executes instructions: how many instruction streams there are, and how many data elements each instruction touches. Between them sits a compiler, runtime or library that maps one onto the other.

Section 2

Hardware, first cut: Flynn's four boxes

In 1966 Michael Flynn classified machines by two counts: how many instruction streams (program counters driving execution) and how many data streams (sets of operands being worked on). Each count is one or many, which gives four boxes. Click a box to see what it means.

Real chips are combinations. A laptop CPU is MIMD across its cores and SIMD inside each core. A GPU is MIMD across its streaming multiprocessors and SIMD-like within each warp. The next section runs one job on seven concrete organizations to show the differences Flynn's boxes hide.

Section 4

Beyond the four boxes: data moves, not instructions

Every machine in Section 3 fetches instructions and reads operands from registers. Three important designs work differently: they cut down instruction fetch and register traffic by letting data flow through a fixed arrangement of arithmetic units.

Systolic arrays: a grid that pumps data

A systolic array is a grid of simple multiply-add cells, each connected only to its neighbours. Values enter at the edges and pulse one cell per clock, like blood through a heart (hence "systolic"). Each value is used by every cell it passes through, so one value read from memory feeds many operations. Google's TPU uses a large systolic array for matrix multiplication. Dataflow: fire when the inputs arrive

A dataflow machine has no program counter. The program is a graph; each operation fires as soon as all its inputs are available, and its result travels as a token to the operations that need it. Independent operations fire in the same step automatically. Pure dataflow computers were a research direction in the 1970s–80s; today the idea lives on inside out-of-order cores (Unit 3), which run a small window of instructions in dataflow order, and in several AI accelerators that map whole computation graphs onto hardware.

Spatial hardware: build the circuit for the loop

FPGAs (field-programmable gate arrays) and CGRAs (coarse-grained reconfigurable arrays) go further: instead of running instructions, you configure the chip into a circuit shaped like your computation. For y = a × b + c that's a multiplier wired to an adder, with registers between them so each stage can work on a different element.

Section 5

Programming models: ten ways to write the same computation

Now the other question. The computation: the sum of squares of eight numbers, x = [3, 1, 4, 1, 5, 9, 2, 6]. The answer is 9 + 1 + 16 + 1 + 25 + 81 + 4 + 36 = 173. It has two parts every parallel program must handle: independent work (squaring each element) and combination (adding the results), which forces the workers to communicate. Most real programs stack several. A typical training job uses data-parallel tensor operations, which a graph compiler fuses into SPMD kernels for a SIMT GPU, with message-passing collectives between GPUs in a BSP rhythm and a pipeline of copies overlapping compute (Unit 6). Recognizing each layer tells you where to look when something is slow.

Check yourselfName the hardware or the model, then say why.
  1. A loop has a data-dependent branch that splits elements roughly half and half. Which machines from Section 3 slow down, and which don't?
    Show answer

    SIMD, vector, SIMT and predicated VLIW slow down: they share one instruction stream across elements, so both paths run with masks and half the slots are wasted. Scalar, multicore and SMT don't, because each instruction stream follows only its own element's path.

  2. Is SMT a kind of SIMD?
    Show answer

    No. SMT runs several instruction streams (it's MIMD in Flynn's terms) that share one core's execution units. SIMD runs one instruction stream over many data elements. A core can have both at once.

  3. Why can a systolic array do a matrix multiply with far fewer memory reads than a scalar core?
    Show answer

    Each value read from memory enters the grid once and is reused by every cell it passes: in a 3 × 3 array, each A and B value takes part in three multiply-adds. A scalar core would reload operands from registers or cache for every multiply-add.

  4. An MPI program starts the same executable on every rank, each branching on its rank number. Which programming model is that?
    Show answer

    SPMD, communicating by message passing. The two aren't exclusive: SPMD says how the program is structured (one program, many instances), message passing says how the instances share data.

  5. Your sum-of-squares code is np.sum(x * x). Who decided how to parallelize it?
    Show answer

    The library (NumPy and its compiled kernels), not you. That's the data-parallel model: you describe whole-array operations, and the implementation chooses the SIMD instructions, loop order and (in some libraries) threads.

For any parallel system, name the programming model you write in, the hardware organization it runs on, and the layer (compiler, runtime or library) that maps one onto the other.
